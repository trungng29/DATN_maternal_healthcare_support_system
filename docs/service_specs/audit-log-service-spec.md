# Audit Log Service — Service Specification

> **Implementation status:** DESIGN — service/source/database chưa tồn tại trong repository tại thời điểm 2026-10-03.  
> **Decision status:** Approved cho boundary append-only, ingest chủ yếu qua RabbitMQ, transactional outbox ở producer, at-least-once và không tạo synchronous dependency cho business transaction.

---

## 1. Tổng quan và boundary

| Thuộc tính | Giá trị |
|---|---|
| Tên service | Audit Log Service |
| Mục đích | Thu nhận, bảo quản bất biến và tra cứu audit fact tối thiểu từ các bounded context. |
| Bounded context | Compliance audit trail; không phải application log, SIEM hay domain source of truth. |
| Actors/Consumers | ADMIN có permission audit; business services qua RabbitMQ; service nội bộ được cấp quyền recovery/query. |
| Source path / port | DESIGN: chưa được tạo/chưa được cấp port; không tự giả định. |
| Public ingress | REST qua Kong; internal synchronous contract dùng gRPC trực tiếp. |

### Chịu trách nhiệm

- AuditEntry append-only, deduplication theo eventId, tra cứu có phân trang và resource-level policy.
- Bảo toàn actor/action/outcome/resource/correlation metadata và thời điểm xảy ra/thu nhận.
- Consumer RabbitMQ idempotent; quarantine/dead-letter audit event không hợp lệ.
- Phát hiện khoảng trống vận hành qua metrics, lag và reconciliation; không làm giao dịch nguồn thất bại vì Audit Service down.

### Không chịu trách nhiệm

- Không xác thực đăng nhập, không thay thế domain event store, application log, tracing hoặc backup.
- Không suy diễn nghiệp vụ từ event thiếu dữ liệu; không sửa state service nguồn.
- Không lưu message body, clinical note, diagnosis, prescription, token, credential hay before/after value nhạy cảm.
- Không cung cấp update/delete API. Retention purge/legal hold chưa được approve và không thuộc MVP.

### Data ownership

Source of truth: AuditEntry và IngestionFailure của Audit Service. actorId, patientId, resourceId và correlationId chỉ là external reference; không có cross-DB FK/query. Domain owner vẫn sở hữu dữ liệu nghiệp vụ gốc.

## 2. Actors và authorization

| Actor/consumer | Hành động | Permission/credential | Resource-level rule |
|---|---|---|---|
| ADMIN | Search/read/export metadata audit | audit:read | Chỉ scope được cấp; truy cập PHI-sensitive category cần audit:read:sensitive và reason. |
| Business service | Publish audit fact | RabbitMQ publisher identity | sourceService phải khớp identity/routing allowlist. |
| Recovery service operator | gRPC IngestAuditEvent | service JWT RS256 + audit:ingest:recovery | Chỉ replay event đã có stable eventId; không dùng trên synchronous business path. |
| Internal compliance/reporting consumer | gRPC query tối thiểu | service JWT + explicit audience/scope | Field allowlist; không bulk dump mặc định. |
| PATIENT/DOCTOR/RECEPTIONIST | Không có public audit API | N/A | 403; không tiết lộ entry tồn tại. |

Kong xác thực JWT ở edge; service vẫn kiểm tra permission. Không tin identity header do client tự gửi. Internal JWT phải có iss, sub, aud, exp, jti và scope hợp lệ; deadline bắt buộc.

## 3. Domain và data model

### Enum

- ActorType: USER, SERVICE, SYSTEM.
- Outcome: SUCCESS, FAILURE, DENIED.
- Sensitivity: STANDARD, SENSITIVE.
- IngestionFailureStatus: QUARANTINED, REPLAYED, DISCARDED.

### AuditEntry (immutable)

| Field | Type | Required | Constraint/mô tả |
|---|---|---:|---|
| id | UUID | Yes | PK, generated by Audit Service. |
| eventId | UUID | Yes | UNIQUE; idempotency key từ producer. |
| eventType/eventVersion | varchar(120)/int | Yes | Version >= 1; allowlist contract. |
| sourceService | varchar(80) | Yes | Khớp authenticated publisher. |
| occurredAt/ingestedAt | timestamptz | Yes | UTC; occurredAt không quá giới hạn future skew. |
| actorType/actorId/actorRole | enum/UUID?/varchar? | Yes/No/No | SYSTEM có thể không có actorId. Không dùng accountId thay business resource ID. |
| action/outcome | varchar(120)/enum | Yes | Stable action name và result. |
| resourceType/resourceId | varchar(80)/UUID? | Yes/No | ID ngoài service; resourceId có thể null cho system action. |
| patientId | UUID | No | Chỉ khi cần filter access/compliance; không FK. |
| correlationId/requestId | UUID/UUID? | Yes/No | Trace flow; không chứa token. |
| reasonCode/reasonText | varchar(80)/varchar(250) | No | reasonText đã sanitize, không PHI chi tiết. |
| changedFields | varchar[] | No | Chỉ tên field allowlisted, không value. |
| sensitivity | enum | Yes | Default STANDARD do producer khai báo và consumer validate. |
| metadata | jsonb | No | Object <= 4 KiB, schema allowlist theo eventType. |
| payloadHash | char(64) | Yes | SHA-256 canonical accepted payload để kiểm chứng duplicate conflict. |

### IngestionFailure

| Field | Type | Constraint |
|---|---|---|
| id | UUID PK | Generated. |
| eventId/sourceService/eventType | UUID?/varchar/varchar? | Metadata tối thiểu; không giữ raw secret payload. |
| reasonCode | varchar(80) | Validation/schema/auth/duplicate conflict. |
| safePayloadDigest | char(64)? | Hash, không raw payload. |
| status | enum | QUARANTINED ban đầu. |
| firstSeenAt/lastSeenAt/attemptCount | timestamptz/timestamptz/int | attemptCount >= 1. |

### Constraints và indexes

| Table | Loại | Fields | Quy tắc |
|---|---|---|---|
| audit_entries | UNIQUE | eventId | Duplicate cùng hash ack; khác hash quarantine. |
| audit_entries | INDEX | occurredAt DESC, id DESC | Cursor stable. |
| audit_entries | INDEX | resourceType, resourceId, occurredAt DESC | Resource history. |
| audit_entries | INDEX | actorId, occurredAt DESC | Actor history. |
| audit_entries | INDEX | correlationId | Trace workflow. |
| audit_entries | INDEX | patientId, occurredAt DESC | Sensitive scoped access. |
| ingestion_failures | UNIQUE | sourceService, eventId, reasonCode | Gộp retry lỗi. |
| audit_entries | CHECK | metadata <= 4096 bytes; occurredAt <= ingestedAt + futureSkew | Bảo vệ abuse/time skew. |

Không có UPDATE/DELETE grant cho application role trên audit_entries. Migration/DB owner tách quyền; mọi insert đi qua validated ingest transaction.

### State machines

AuditEntry: chỉ CREATED, không transition. IngestionFailure: QUARANTINED → REPLAYED hoặc DISCARDED; thao tác cần ADMIN permission và reason, bản ghi failure vẫn tồn tại.

## 4. REST và gRPC contracts

- OpenAPI: docs/api-specs/audit-log-service.yaml
- Proto: docs/grpc/audit_log/v1/audit_log_internal.proto
- Base path: /api/audit-logs

| ID | Method/path | Mục đích | Quyền |
|---|---|---|---|
| AUD-API-001 | GET /health | Liveness | Public/internal |
| AUD-API-002 | GET /ready | DB + consumer readiness | Internal/ops |
| AUD-API-003 | GET /entries | Search cursor-based | audit:read |
| AUD-API-004 | GET /entries/{entryId} | Chi tiết allowlisted | audit:read + scope |
| AUD-API-005 | GET /resources/{resourceType}/{resourceId}/entries | Lịch sử resource | audit:read + scope |

Search filters: from/to UTC (to exclusive), sourceService, eventType, actorId, resourceType/resourceId, patientId, correlationId, outcome, sensitivity; limit 1..100 default 50; cursor opaque. Khoảng mặc định 24 giờ, tối đa 31 ngày/request. Kết quả sort occurredAt DESC, id DESC. Không có public write/export API MVP.

Errors dùng envelope error.code/message/requestId; 400 VALIDATION_FAILED, 401 UNAUTHENTICATED, 403 FORBIDDEN, 404 AUDIT_ENTRY_NOT_FOUND, 413 PAYLOAD_TOO_LARGE, 429 RATE_LIMITED, 503 DEPENDENCY_UNAVAILABLE. Với resource không được phép xem, trả 404 để chống enumeration khi policy yêu cầu.

### gRPC

- IngestAuditEvent: recovery/reconciliation only; idempotent theo eventId + payloadHash; deadline <= 2s; không được gọi trong critical business transaction.
- GetAuditEntry: lookup tối thiểu theo ID, permission context từ verified service JWT.
- SearchAuditEntries: internal bounded query, pageSize <= 100, range <= 31 ngày.
- Health: trạng thái process/DB/consumer lag.

gRPC status: INVALID_ARGUMENT, UNAUTHENTICATED, PERMISSION_DENIED, NOT_FOUND, ALREADY_EXISTS khi same eventId khác payload, RESOURCE_EXHAUSTED, UNAVAILABLE. Proto DTO là contract riêng, không share DB entity.

## 5. Business rules

| Rule ID | Quy tắc | Enforced by | Error/handling |
|---|---|---|---|
| AUD-BR-001 | AuditEntry đã accepted không được update/delete bởi application. | DB + app | FORBIDDEN/DB revoke |
| AUD-BR-002 | Producer ghi audit fact vào transactional outbox cùng local mutation; Audit outage không rollback business transaction. | Producer architecture | Async retry |
| AUD-BR-003 | eventId duy nhất; duplicate cùng canonical hash được ack không insert; khác hash quarantine. | DB + consumer | DUPLICATE_EVENT_CONFLICT |
| AUD-BR-004 | Chỉ field allowlist, minimum necessary; changedFields không chứa value. | Consumer schema | EVENT_SCHEMA_INVALID |
| AUD-BR-005 | Publisher identity phải khớp sourceService/routing key. | Broker + consumer | PUBLISHER_MISMATCH |
| AUD-BR-006 | occurredAt UTC; business date nếu hiển thị dùng Asia/Ho_Chi_Minh, không đổi instant. | API | VALIDATION_FAILED |
| AUD-BR-007 | Sensitive query cần permission bổ sung và reason; chính thao tác đọc phải phát audit fact riêng, tránh recursive body. | Authz + outbox | FORBIDDEN |
| AUD-BR-008 | Không trả raw metadata key chưa allowlist. | Serializer | Field omitted |
| AUD-BR-009 | Event invalid không retry vô hạn; bounded retry rồi DLQ/quarantine và alert. | Consumer | Ack/DLQ |
| AUD-BR-010 | Ingest gRPC là recovery path, không được biến thành dependency đồng bộ của mutation nguồn. | Architecture test/review | Reject policy |

### AUD-SCN-001 — Ingest thành công

~~~gherkin
Given Billing đã commit payment và audit fact eventId E trong cùng local outbox
When outbox relay publish E và Audit consumer nhận event hợp lệ
Then một AuditEntry immutable được insert với correlationId và occurredAt gốc
And message chỉ được ack sau local commit
And không có synchronous callback tới Billing
~~~

### AUD-SCN-002 — Redelivery

~~~gherkin
Given eventId E đã được lưu với payloadHash H
When RabbitMQ redeliver E với cùng canonical payload H
Then consumer ack
And không tạo entry hoặc side effect thứ hai
~~~

### AUD-SCN-003 — Reuse eventId khác payload

~~~gherkin
Given eventId E đã tồn tại với hash H1
When E đến với hash H2 khác H1
Then không thay thế AuditEntry
And tạo/gộp IngestionFailure DUPLICATE_EVENT_CONFLICT và alert
~~~

### AUD-SCN-004 — Sai scope

~~~gherkin
Given ADMIN có audit:read nhưng không có audit:read:sensitive
When gọi GET entry SENSITIVE
Then trả 404 hoặc 403 theo anti-enumeration policy thống nhất
And không trả metadata
And phát audit fact access_denied bất đồng bộ
~~~

### AUD-SCN-005 — Audit Service hoặc broker gián đoạn

~~~gherkin
Given domain mutation hợp lệ và audit fact đã nằm trong local outbox
When broker hoặc Audit Service unavailable
Then domain transaction vẫn thành công
And relay retry có backoff đến khi publish được
And lag threshold tạo operational alert
~~~

### AUD-SCN-006 — Event đến sai thứ tự

~~~gherkin
Given update event U đến trước create event C của cùng resource
When cả hai có eventId riêng và schema hợp lệ
Then cả hai được lưu theo occurredAt gốc và ingestedAt thực tế
And Audit Service không suy diễn hay sửa state domain
~~~

## 7. Edge cases

- Missing/unknown schema version, invalid UUID/timestamp, metadata > 4 KiB: quarantine, không insert entry.
- occurredAt quá xa tương lai: quarantine; event cũ vẫn accepted vì audit history, gắn metric late_event.
- Cursor malformed/expired, from >= to, range > 31 ngày: 400.
- DB commit rồi ack thất bại: redelivery được dedup.
- Consumer crash trước commit: message requeue; không ack sớm.
- Pagination khi có insert mới: keyset cursor không duplicate/skip các row đã nằm trước cursor.
- PII/PHI/secret trong metadata không allowlist: reject hoặc strip theo versioned schema; không log raw event.
- Clock/date: lưu UTC; filter to exclusive; business-day rendering Asia/Ho_Chi_Minh.

## 8. Integrations, events và failure

### Dependencies

| Dependency | Required cho ingest/query? | Failure behavior |
|---|---:|---|
| PostgreSQL riêng | Yes | Not-ready/UNAVAILABLE; không ack message. |
| RabbitMQ | Yes cho primary ingest | Consumer reconnect bounded backoff; producer outbox giữ event. |
| Auth public keys/service JWT trust | Yes cho REST/gRPC | Reject fail-closed; normal JWT verification không gọi Auth mỗi request. |

Inbound routing key: audit.recorded.v1 (hoặc per-source binding được infrastructure approve). Envelope bắt buộc: eventId, eventType, eventVersion, occurredAt, correlationId, producer, data. data là AuditFact contract, không phải DB entity. Delivery at-least-once; durable queue, publisher confirm, DLQ. Broker topology/exchange name là CONFIG/DESIGN, chưa xác nhận trong repo.

Audit Service không cần outbox cho ingest. Nếu phát audit.ingestion_quarantined.v1 hoặc audit.access_detected.v1 cho monitoring, ghi local outbox cùng transaction; event không chứa raw payload/PHI.

## 9. Security, audit, NFR và config

- TLS nội bộ theo platform; encryption at rest; DB credential qua secret store; least privilege.
- Log chỉ eventId/source/type/errorCode/requestId, không body/token/Authorization.
- Rate-limit search; export disabled; query reason và actor được audit.
- Target DESIGN: ingest P95 <= 500 ms từ broker receipt không tính broker lag; REST search P95 <= 1 s cho bounded indexed query; availability không được ảnh hưởng domain availability.
- Metrics: consumed/duplicate/quarantined/DLQ, ingest latency, queue lag, query latency/denied, DB errors.

- Unit: schema allowlist/redaction, canonical hash, permission, cursor, UTC boundaries.
- DB integration: insert-only privilege, unique eventId race, indexes/query plan, rollback trước ack.
- Contract: OpenAPI 3.0.3, proto compile, event fixtures từng version.
- RabbitMQ integration: redelivery, out-of-order, poison event, DLQ, reconnect.
- Security: publisher spoof, JWT aud/scope, sensitive read, mass assignment, log leak.
- Load: sustained ingest và bounded search không starvation consumer.

## 11. Implementation phases

1. Foundation: service skeleton, DB riêng, migrations/insert-only grants, JWT, health/readiness.
2. Ingest: event schema registry, RabbitMQ consumer, dedup/quarantine/DLQ, observability.
3. Query: REST/gRPC, keyset pagination, field allowlist, sensitive authorization.
4. Hardening: producer contract tests, replay tooling có approval, load/security/recovery tests.

Release gate: broker topology, service port, retention/legal hold và permission-role mapping phải được owner/infra/security phê duyệt; không tự chọn dependency/provider mới.
